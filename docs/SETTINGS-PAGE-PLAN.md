# Settings 页面开发计划

按下面的顺序实现 Settings 页面。前半部分先完成可用的前端原型；账号和数据库能力接入后，再完善跨设备保存及账户隐私功能。所有偏好数据功能都必须通过独立的存储接口读写，页面组件不得直接依赖浏览器存储、数据库或具体后端服务。

| 顺序 | 阶段               | 任务                                                                                            | 完成标准                                                                       |
| ---- | ------------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 1    | 创建页面           | 新建 `/settings` 页面和 Settings 页面组件，沿用项目现有的导航、字体、颜色和布局风格。           | 访问 `/settings` 能看到页面标题、简介和设置区域。                              |
| 2    | 接通导航           | 将导航栏中的 Settings 从预览按钮改为指向 `/settings` 的链接，并显示当前页面状态。               | 从首页点击 Settings 可以进入页面；在设置页能看出当前导航位置。                 |
| 3    | 添加教练语气       | 提供鼓励型、平衡型、直接型三个选项，并附简短说明。                                              | 玩家能选择一个语气，页面能正确显示当前选择。                                   |
| 4    | 添加解释详细程度   | 提供简短、标准、详细三个选项，解释各自会改变什么。                                              | 玩家能选择一个详细程度，页面能正确显示当前选择。                               |
| 5    | 添加玩家档案偏好   | 提供经验水平、玩家目标、竞争倾向等字段；目标允许选择或填写。                                    | 设置页能展示和编辑这些偏好，字段含义清楚。                                     |
| 6    | 实现编辑操作       | 每个功能区提供单独保存和重置；页面另提供保存全部、放弃全部和重置全部；重置操作前显示确认。      | 单区操作只影响该区；全局操作影响所有设置；保存状态和未保存状态有明确反馈。     |
| 7    | 保存原型偏好       | 在存储接口后新增/替换浏览器本地存储实现；页面打开时读取已保存值，不改动页面组件和偏好业务逻辑。 | 刷新页面后偏好仍保留；清除浏览器数据后回到默认值；切换存储实现不要求重写页面。 |
| 8    | 完善可访问性和适配 | 为控件添加标签、键盘操作和焦点样式，并检查窄屏布局。                                            | 不依赖鼠标也能完成设置；手机宽度下内容不溢出。                                 |
| 9    | 接入账号存储       | 账号系统和后端存储可用后，将本地原型存储替换或迁移为用户账户偏好。                              | 登录用户在不同设备登录时能读取自己的偏好，用户之间数据隔离。                   |
| 10   | 增加隐私与账户入口 | 账户和数据删除功能实现后，在设置页增加相关入口，并为删除等不可逆操作提供说明和确认。            | 玩家能找到账户隐私管理入口，操作影响和后果清楚。                               |

### 解耦开发约定（后续功能必须遵守）

- 页面组件只负责展示和用户交互；偏好类型、默认值、分区合并/比较、状态管理和存储实现分别放在 `lib/settings/`。
- 业务逻辑通过 `SettingsRepository` 的 `load` / `save` 接口访问数据，不在 React 页面或 Hook 中直接调用 `localStorage`、数据库 SDK 或具体 API。
- 新增偏好字段时，需同步更新类型、默认值、复制/比较/分区合并逻辑及存储序列化，并检查旧数据缺字段时的兼容行为。
- 第 7 步通过现有接口使用浏览器本地存储仓库，界面和业务操作保持不变；第 9 步接入账户后，再以服务端账户仓库替换或迁移。数据库选型不阻碍接口和业务层先行开发。
- 每个后续步骤都要先实现并自测，再由用户测试；用户确认通过后才把对应验收标记改为“已验收”。

## 页面范围

- Settings 管理教练沟通偏好和玩家辅导档案。
- 排名、胜率、游戏历史和进步趋势放在 Profile。
- AI 对话和 Current Focus 推荐放在 Coaching。
- 玩家目标可帮助教练调整表达和建议方式，但不能直接修改排名、比赛结果、官方统计或分析结论。
- AI 可以讨论偏好，但保存偏好必须由页面中的应用控件完成。
